# ReadyType 1.6.0 实施计划

## 成功标准

本版本成功不以“新增了按钮”衡量，而以三项结果衡量：用户更少手动选择场景、选中文字能安全完成修改、聊天与邮件输出在真实 App 中明显符合语境。

## 第 0 阶段：冻结基线

- 从现有匿名统计记录 1.5.0 的输出方式采用率、场景分布、完成率、取消率、错误码和完成耗时分桶。
- 不读取或导出任何用户文本。
- 冻结 1.6.0 黑盒测试语料和六类 App 矩阵，后续不得通过修改测试句迎合实现。

验证结果：形成一份不含用户内容的基线快照，并确定本版本主要指标。

当前证据：匿名字段口径与固定 App 验收矩阵已冻结；当前生产样本不足，不输出无统计依据的采用率结论，待形成首批真实样本后补齐快照。

## 第 1 阶段：统一 Context Engine

1. 新增 `AppProfile`、`InputIntent`、`OutputTone`、`ContextReason` 和 `ContextDecision`。
2. 将现有 `OutputScenario.infer` 与 `ChatTone.infer` 迁移到单一决策入口。
3. 建立集中式 `AppProfileCatalog`，保留未知 App 的通用降级。
4. 保持现有 UI 和输出行为，先用并行计算或测试适配验证新旧决策一致性。
5. 删除仅由本次迁移产生的重复判断，不顺手重构 Prompt 或识别器。

验证：决策优先级、Profile 映射、语义降级和旧行为兼容测试；分类 P95 < 10ms。

状态：已完成。`ContextEngineTests` 与旧 `OutputScenarioTests` 共 18 项聚焦测试通过；全量 409 项测试无失败，分类基准 P95 为 0.062ms，生产 `.app` 构建通过。

## 第 2 阶段：选区捕获与安全替换

1. 新增 `ActiveTextContextProvider`，只读取当前明确选区。
2. 新增 `SelectionFingerprint` 和 `SelectionReplacementGuard`。
3. 扩展现有 `PasteService` 的选区能力，但普通粘贴路径保持不变。
4. 覆盖选区不变、选区变化、焦点变化、App 切换、不可访问元素和超长文本。
5. 任何验证失败均复制降级，禁止覆盖新内容。

验证：单元测试、TextEdit 集成测试、错误窗口零写入门槛；选区读取与验证 P95 < 50ms。

状态：已完成。新增显式选区读取、目标与选区指纹、安全替换及复制降级；32 项聚焦测试与 420 项全量测试无失败，指纹验证 P95 为 0.000ms，TextEdit 固定夹具真实替换通过，生产 `.app` 构建通过。测试诊断入口必须显式设置环境变量，正常启动不会启用。

## 第 2.1 阶段：长句准确度与响应速度收口

1. 自动高精度边界从 12 秒调整为 8 秒。
2. 自动模式并行运行极速与高精度识别；高精度 3 秒内完成则采用，否则直接使用并行结果。
3. DeepSeek 改写明确关闭 thinking，并设置 1,024 token 输出上限。
4. 最近结果分别展示识别与整理输入耗时，不用总耗时掩盖慢链路。

验证：路由边界、并行启动、超时不重复识别、请求体和计时文案测试；真实长句记录原始识别、实际引擎和分段耗时。

状态：代码、聚焦测试、421 项全量测试、生产构建和敏感信息扫描已通过；发布前仍需完成一次真实长句分段耗时验收。

## 第 3 阶段：选中文字语音操作

1. 新增有限动作：缩短、扩写、自然化、正式化、整理、翻译成英文、回复。
2. `SelectionIntentResolver` 只在明确指令时进入 AI 选区操作；普通口述仍走现有模式。
3. `SelectionActionProcessor` 复用 DeepSeek Provider 和现有错误映射。
4. Prompt 必须保留事实、名称、数字、日期和承诺，不得补充用户未提供的信息。
5. DeepSeek 失败时不触发普通文本回退覆盖原文。

验证：固定输入/输出契约测试、失败保持原文测试、8,000 字符上限测试和 API 连接失败测试。

## 第 4 阶段：场景语气与 HUD

1. 个人聊天、工作聊天、邮件、笔记、文档和 AI 工具分别建立正例与负例。
2. 将 Prompt 统一消费 `ContextDecision`，移除调用点自行推断场景。
3. 选中文字时 HUD 只调整状态文案，不改变胶囊尺寸和视觉系统。
4. 最近结果显示用户可理解的场景说明；设置保留手动兜底。
5. 新增匿名事件字段：动作类型、Profile、结果、长度和耗时分桶。

验证：Prompt 单元测试、HUD 状态测试、匿名字段白名单测试和六类 App UI 冒烟。

## 第 5 阶段：真实黑盒与发布

- 六类 App 各执行普通输入、选中文字修改、目标变化和取消路径。
- 中文、英文和中英混合各至少一组；个人聊天和邮件必须包含负样本。
- 运行 `swift test`、`scripts/build-app.sh`、`scripts/verify-ui.sh`、`scripts/verify-release-local.sh` 和 `python3 scripts/check-sensitive-info.py`。
- 同步中英文 README、CHANGELOG、版本文档和黑盒检查。
- 版本号与构建号只在功能进入可测试开发构建时升级；规划阶段公开应用仍为 1.5.0。
- 发布后验证 GitHub Actions、latest Release、DMG、ZIP 和 SHA-256。

## 预计开发轮次

1. Context Engine 与兼容测试。
2. 选区捕获、指纹与安全替换。
3. 选中文字动作与 DeepSeek 处理。
4. 场景语气、HUD 和匿名统计。
5. 跨 App 黑盒、修复、打包和发布。

每轮必须有独立可验证结果；同一缺陷最多允许一次针对架构的修复和一次回归验证，不进入无边界追加语料循环。

## 发布门槛

- P0 需求全部完成，P1 可以延后但必须在黑盒文档标明。
- 自动化测试无失败，外部环境跳过项有明确原因。
- 选区变化与错误窗口覆盖测试 100% 通过。
- 真实 App 矩阵完成且保留证据。
- 不存在用户内容、密钥、私人路径或内部素材泄露。

## 1.7.0 候选

- 在用户手动修改 ReadyType 刚输出的文本后，使用短时、范围受限的本地差异检测。
- 同一纠正重复出现后再提示，用户确认才加入常用词。
- 支持撤销、忽略和删除，不保存完整输入正文。

该候选不阻塞 1.6.0，也不得提前混入本版本实现。
